<section>
    <h1>Pizza as a Service 2.0</h1>
    <p>Modelos de Servicio en la Nube</p>
    <p>Javier Rodríguez Rodríguez</p>
</section>

<section>
    <h2>La Analogía 2.0</h2>
    <p>
        Una forma sencilla de entender el <strong>Modelo de Responsabilidad Compartida</strong> en la computación moderna.
    </p>
    <ul>
        <li><strong>La cocina y el horno:</strong> Infraestructura (Hardware, Red).</li>
        <li><strong>La masa:</strong> Entorno de ejecución y SO.</li>
        <li><strong>Los ingredientes:</strong> Tus aplicaciones y datos.</li>
    </ul>
</section>

<section>
    <section>
        <h2>1. On-Premises (La Pizza Casera)</h2>
        <p>Tú gestionas y mantienes absolutamente todo.</p>
        <p><em>↓ Usa la flecha abajo para profundizar</em></p>
    </section>

    <section>
        <h2>Descripción</h2>
        <p>
            El modelo tradicional. La empresa es dueña de la infraestructura física, la red, los sistemas operativos, los datos y las aplicaciones. Tú pones la cocina, el gas, la masa y los ingredientes.
        </p>
    </section>

    <section>
        <h2>Ventajas y Desventajas</h2>
        <ul>
            <li><strong>Ventajas:</strong> Control absoluto sobre la seguridad, datos y hardware físico.</li>
            <li><strong>Desventajas:</strong> Altos costos iniciales (CapEx), mantenimiento complejo, difícil de escalar rápidamente.</li>
        </ul>
    </section>

    <section>
        <h2>Casos de Uso y Ejemplos</h2>
        <ul>
            <li><strong>Casos de uso:</strong> Sistemas gubernamentales, regulaciones de soberanía de datos, control industrial.</li>
            <li><strong>Ejemplos:</strong> Un Centro de Datos (Data Center) corporativo en las oficinas de la empresa.</li>
        </ul>
    </section>
</section>

<section>
    <section>
        <h2>2. IaaS (La Cocina Alquilada)</h2>
        <p>Infrastructure as a Service</p>
        <p><em>↓ Usa la flecha abajo para profundizar</em></p>
    </section>

    <section>
        <h2>Descripción</h2>
        <p>
            El proveedor te alquila el hardware físico y la red. Tú traes tu propio sistema operativo, bases de datos y aplicaciones. (El proveedor pone el horno; tú traes la masa y los ingredientes).
        </p>
    </section>

    <section>
        <h2>Ventajas y Desventajas</h2>
        <ul>
            <li><strong>Ventajas:</strong> Cero mantenimiento de hardware físico, pago por uso (OpEx), escalabilidad rápida.</li>
            <li><strong>Desventajas:</strong> Aún requiere administración intensiva de sistemas (parches del SO, seguridad de red).</li>
        </ul>
    </section>

    <section>
        <h2>Casos de Uso y Ejemplos</h2>
        <ul>
            <li><strong>Casos de uso:</strong> Migraciones "Lift and Shift", entornos de pruebas, almacenamiento masivo.</li>
            <li><strong>Ejemplos:</strong> Amazon EC2, Azure Virtual Machines, Google Compute Engine.</li>
        </ul>
    </section>
</section>

<section>
    <section>
        <h2>3. CaaS (La Base de Pizza Lista)</h2>
        <p>Containers as a Service</p>
        <p><em>↓ Usa la flecha abajo para profundizar</em></p>
    </section>

    <section>
        <h2>Descripción</h2>
        <p>
            Un punto intermedio. El proveedor gestiona el hardware y el Sistema Operativo subyacente (el clúster). El usuario despliega y gestiona sus contenedores. (El proveedor pone el horno y la masa; tú los ingredientes).
        </p>
    </section>

    <section>
        <h2>Ventajas y Desventajas</h2>
        <ul>
            <li><strong>Ventajas:</strong> Portabilidad extrema del código, despliegues ultra rápidos, gran aislamiento.</li>
            <li><strong>Desventajas:</strong> Curva de aprendizaje empinada para la orquestación, redes complejas.</li>
        </ul>
    </section>

    <section>
        <h2>Casos de Uso y Ejemplos</h2>
        <ul>
            <li><strong>Casos de uso:</strong> Arquitecturas de microservicios, pipelines de integración continua (CI/CD).</li>
            <li><strong>Ejemplos:</strong> Amazon EKS, Azure Kubernetes Service (AKS), Google Kubernetes Engine (GKE).</li>
        </ul>
    </section>
</section>

<section>
    <section>
        <h2>4. PaaS (La Pizza a Domicilio)</h2>
        <p>Platform as a Service</p>
        <p><em>↓ Usa la flecha abajo para profundizar</em></p>
    </section>

    <section>
        <h2>Descripción</h2>
        <p>
            El proveedor gestiona todo (hardware, SO, entorno de ejecución). El desarrollador solo se enfoca en escribir el código y subir sus datos. (Te entregan la pizza horneada; tú solo te la comes).
        </p>
    </section>

    <section>
        <h2>Ventajas y Desventajas</h2>
        <ul>
            <li><strong>Ventajas:</strong> Acelera el desarrollo, cero mantenimiento de servidores, auto-escalado simple.</li>
            <li><strong>Desventajas:</strong> Riesgo de "Vendor Lock-in" (atadura al proveedor), menor control de infraestructura.</li>
        </ul>
    </section>

    <section>
        <h2>Casos de Uso y Ejemplos</h2>
        <ul>
            <li><strong>Casos de uso:</strong> Lanzamiento rápido de APIs, desarrollo de aplicaciones web, startups (MVP).</li>
            <li><strong>Ejemplos:</strong> Heroku, AWS Elastic Beanstalk, Vercel.</li>
        </ul>
    </section>
</section>

<section>
    <section>
        <h2>5. FaaS / Serverless (Pedir por Porciones)</h2>
        <p>Function as a Service</p>
        <p><em>↓ Usa la flecha abajo para profundizar</em></p>
    </section>

    <section>
        <h2>Descripción</h2>
        <p>
            Subes pequeños fragmentos de código que solo se ejecutan cuando un evento los activa. El servidor solo existe durante los milisegundos que tu código corre. Pagas exactamente por cada "mordisco".
        </p>
    </section>

    <section>
        <h2>Ventajas y Desventajas</h2>
        <ul>
            <li><strong>Ventajas:</strong> Pagas solo por milisegundos de ejecución (cero uso = cero costo), escala al infinito al instante.</li>
            <li><strong>Desventajas:</strong> Latencia en arranques en frío (Cold Starts), difícil de depurar, caro para tareas muy largas.</li>
        </ul>
    </section>

    <section>
        <h2>Casos de Uso y Ejemplos</h2>
        <ul>
            <li><strong>Casos de uso:</strong> Procesamiento de imágenes bajo demanda, chatbots, tareas programadas (cron jobs).</li>
            <li><strong>Ejemplos:</strong> AWS Lambda, Azure Functions, Google Cloud Functions.</li>
        </ul>
    </section>
</section>

<section>
    <section>
        <h2>6. SaaS (Cenar en la Pizzería)</h2>
        <p>Software as a Service</p>
        <p><em>↓ Usa la flecha abajo para profundizar</em></p>
    </section>

    <section>
        <h2>Descripción</h2>
        <p>
            El proveedor gestiona toda la pila tecnológica de principio a fin. El usuario final simplemente consume la aplicación a través de internet. (Vas, pides, comes; el restaurante hace todo).
        </p>
    </section>

    <section>
        <h2>Ventajas y Desventajas</h2>
        <ul>
            <li><strong>Ventajas:</strong> Accesibilidad instantánea, cero mantenimiento o instalación, actualizaciones invisibles.</li>
            <li><strong>Desventajas:</strong> Control nulo sobre el backend o los datos crudos, dependencia total de la conexión a internet.</li>
        </ul>
    </section>

    <section>
        <h2>Casos de Uso y Ejemplos</h2>
        <ul>
            <li><strong>Casos de uso:</strong> Correo electrónico, herramientas de ofimática, plataformas CRM y ERP.</li>
            <li><strong>Ejemplos:</strong> Google Workspace, Microsoft 365, Salesforce, Netflix.</li>
        </ul>
    </section>
</section>
